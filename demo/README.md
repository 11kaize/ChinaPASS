# ChinaPASS Demo

在线版入口：<https://11kaize.github.io/ChinaPASS/>

ChinaPASS 面向来华访客，提供城市探索、简易行程、行前准备清单、多语释义中文短句和紧急拨号入口。静态内容支持离线访问，也可以把短句或自填中文地址全屏展示给身边的人看。

## 当前功能

- 浏览 9 个实用旅行场景，查看操作步骤、常见问题、备选方案和官方来源
- 搜索与筛选 6 座城市，查看原创速览、看点和官方或权威来源
- 把城市加入个人行程，调整顺序与停留天数，或套用可编辑的 7 天和 10 天样例
- 阅读证件核对、景点预约和离线准备 3 篇新增攻略，与原有 9 个场景构成攻略库
- 填写中文目的地名称、地址和可选联系电话，生成全屏求助卡；可随时清除本机保存的数据
- 搜索并浏览 14 组共 96 条双语短句
- 将中文短句全屏展示，隐藏释义、复制中文、键盘翻页
- 勾选行前准备清单，保存到本机
- 查看 7 条常见问题，记录各场景的逐步完成情况
- 从首页拨打 110 报警、120 急救、119 火警或 122 交通事故电话，或打开中文求助卡
- **EN / 中文 / 日本語 / 한국어** 四语种切换
- 城市、行程和新增攻略的详细说明目前为英文；首页和个人地址卡支持四语种，原有场景内容继续支持四语种，求助卡中文正文保持不翻译
- 自动定位城市（离线匹配，坐标不出设备），或手动选城市
- 4 屏首启引导，讲清「怎么用」
- 将网站安装为 PWA，缓存静态应用资源供离线使用
- 使用 Electron 将同一静态页面打包为桌面应用，参阅仓库根目录 [DESKTOP.md](../DESKTOP.md)

> 因为用了 `file://`，`localStorage` 在个别浏览器隐私模式下可能不可用 —— 已做降级处理；本机行程、地址、清单和勾选进度可能无法跨次保存，不影响当次使用。
> 同一原因，**`file://` 下浏览器会直接拒绝定位请求**（Chrome 报 code 1「Only secure origins are allowed」）。这是预期内的降级路径，会引导用户手动选城市，不是 bug；线上 https 部署可正常定位。同理，**PWA 安装和 Service Worker 离线缓存也需要 HTTP 或 HTTPS**，直接双击打开时安装按钮不会出现。

## 本地运行网页

在 `demo/` 目录执行：

```bash
python3 -m http.server 4173
```

打开 <http://localhost:4173>。直接打开 `index.html` 也能使用短句与清单；PWA 安装和 Service Worker 离线缓存需要通过 HTTP 或 HTTPS 访问。

交互细节：

- 步骤点击打卡 + 行前清单勾选 + 进度记忆（`localStorage`）
- 场景页顶部有页内跳转目录，按**实际渲染出的段落**生成（某场景没有「备选方案」就没有那一项）。它是**一行可横滑的短标签**，标签由 `toc*` 一组独立的短 key 提供，**不是段落标题** —— 段落标题可以写「备用方案 —— 主路径失败时」，导航标签不行：直接复用标题会让 8 项绕成 4 行、占掉手机屏幕五分之一
- 全屏卡片：左右切换、`Esc` 关闭、方向键翻页、`Hide English`、`Copy 中文`
- 搜索实时过滤场景与卡片
- 深色模式跟随系统
- 桌面端自动收成手机宽度居中显示
- 动效基本是纯 CSS，**跟随系统的「减少动态效果」自动关闭**。唯一的例外是页内跳转的平滑滚动——那只能用 JS，所以它在 `jumpTo()` 里单独判断了一次 `prefers-reduced-motion`（CSS 的全局开关管不到 JS 滚动）

## 多语言的设计边界（改这块之前先读）

**卡片上的中文是「递给中国人看的那句话」，是载荷，永不翻译。**
语言切换只改变两件事：卡片下面的释义，以及整个界面的说明文字。

这条边界决定了数据结构：

- `card.zh`、`showCard.lines[]` 是**不可变载荷**，四语种下逐字节相同
- `en` / `ja` / `ko` 是**释义**，给使用者自己看懂用
- 界面语言选中文时，**不显示释义**（看的人本来就是中文使用者），连「显示英文」按钮一起隐藏
- **全屏卡片页永远不出现任何「待翻译」痕迹** —— 那一屏是递给陌生人看的

内容分两层：

| 层 | 位置 | 现状 |
|---|---|---|
| 界面外壳 | `UI` 字典，`t(key)` 取 | 四语种齐全（103 个 key） |
| 场景元信息、卡片组标题、卡片释义、FAQ、引导、行前清单 | 直接挂在对象上，`L(v)` 取 | 四语种齐全 |
| **场景正文**（steps / mistakes / planB / trouble / before / tip / disclaimer） | 同上 | **只有英文**，其余语种回落英文 |

正文缺失时**不做逐条标记**，而是在该页面顶部显示一条横幅（「このページはまだ翻訳が完了していません」），
并在语言选择页提前标注哪些语言「部分页面为英文」。
补翻译时直接在字段上加 `zh` / `ja` / `ko` 键即可 —— **横幅会自己消失**，不用记得回来删。

> ⚠️ 日韩文案是初稿，未经母语者复核。正文部分（含政策内容）刻意没有机翻成日韩 —— 见 [docs/09-风险与合规.md](../docs/09-风险与合规.md)。

## 内容规模

```
9 个场景 · 96 张双语卡片（14 组）· 7 条行前清单 · 7 条 FAQ · 4 屏引导 · 20 个城市
```

行前清单（`#/prep`）按落地前的时间顺序排：**护照签证 → 上网 → 离线 app → 支付 → 中文地址 → 地图 → 紧急联系人**。
勾选状态存在 `ccs.v2.prep`，首页有一张「N / M ready」的预告条，全勾完弹一次提示。

场景按落地时间线：**入境通关** · SIM · 支付 · 打车 · 酒店 · 地铁 · 高铁 · 外卖 · 紧急

卡片组按紧急程度从高到低：紧急 → 医院 → 丢失物品 → 手机没电 → 海关 → 找路 → 厕所 → 打车 → 酒店 → 外卖 → 支付 → 地铁 → 高铁 → SIM

## 内容边界

当前 Demo 不提供地图导航、付款、打车、铁路订票、实时翻译或紧急调度服务。短句仅用于沟通；政策及服务可用性会变化，出行前请查看相关服务方的最新说明。

## 文件结构

```
demo/
├── index.html           页面骨架 + 全屏卡片层 + 首启引导层
├── styles.css           全部样式（含深色模式与全部 @keyframes）
├── data.js              内容层：SCENES / CARD_GROUPS / UI / ONBOARDING / PREP / CITY_BOXES / FAQ
├── explore.js           六座城市与三篇新增短攻略
├── explore-ui.js        城市、行程、攻略库和地址卡交互
├── hero-rail.png        原创生成的首页旅行主视觉
├── app.js               主路由 + 多语言场景渲染（无依赖）
├── manifest.webmanifest PWA 清单
├── sw.js                离线外壳缓存
└── icon.svg / icon-192.png / icon-512.png
```

**内容与代码是分离的。** `data.js` 保存场景与短句，`explore.js` 保存城市和新增攻略。后续接入内容系统时，可以替换这些静态数据来源。

更新离线内容时，**递增 `sw.js` 中的缓存版本号**（`CACHE_NAME` 末尾的日期序号），否则老用户会一直拿到缓存里的旧外壳。

新增卡片必须先补进 [`content/cards/双语急救卡片.md`](../content/cards/双语急救卡片.md)（卡片的源头文件），再接进 demo。该文件末尾有一张组名对应表。

### 两个刻意的约束

1. **顶层 `const` 不是 `window` 上的属性。** `data.js` 用 `const` 声明，所以 `SCENES`、`UI` 这些是全局词法绑定，`window.SCENES` 是 `undefined`。写校验脚本时要用 `vm.runInContext("SCENES", ctx)` 读。
2. **不要改成 ES module。** `<script type="module">` 在 `file://` 下会被 CORS 拦掉，`fetch()` 读 `.json` 同样不行。「双击即开、无构建、可离线」是这个项目已经立住的性质。

## 与文档的偏差（需要确认）

1. **步骤数超出规范。** [04-号文档](../docs/04-页面结构与用户流程.md) 要求「任何场景的主路径不超过 7 步」。新增的 `customs` 和 `sim` 是 7 步（合规），`emergency` 6 步，但 **6 个场景超标**：Pay 8 / Taxi 8 / Hotel 8 / Metro 8 / Food 9 / Train 10。要么压缩，要么把超出的部分移到「进阶」区。
2. **截图红框未实现。** 文档要求「截图 + 红框 + 分步指引」，demo 里只有文字步骤 —— 需要真实截图素材才能做。
3. **内容准确性待复核。** 支付限额、12306 规则、酒店接待外籍政策、海关流程都只写了操作步骤、未写具体数字。上线前仍需对照官方渠道逐条核对。
4. **`customs` / `sim` / `hotel` 是政策类内容，风险最高。** 已严格只写操作步骤 + 官方来源 + 免责声明，但**不建议跳过人工复核**。
