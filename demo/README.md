# China Cheat Sheet — Demo

可交互的移动端原型，实现 [docs/03-功能设计.md](../docs/03-功能设计.md) 和 [docs/04-页面结构与用户流程.md](../docs/04-页面结构与用户流程.md) 里描述的 MVP 形态。

## 打开方式

**直接双击 `index.html`** 即可。无需安装依赖、无需构建、无需联网。
按 `F12` → 切换到手机模拟视图（iPhone / Pixel）查看真实移动端效果。

> 因为用了 `file://`，`localStorage` 在个别浏览器隐私模式下可能不可用 —— 已做降级处理，只影响勾选进度的记忆，不影响功能。

## 已实现的功能

| 文档里的设计 | demo 中的实现 |
|---|---|
| 首页「任务入口」而非菜单 | 8 个场景卡片，P0 场景带角标 |
| 场景详情页 7 段结构 | Task / Before You Start / Step-by-Step / Common Mistakes / Useful Chinese Cards / Plan B / If Something Goes Wrong |
| 双语急救卡片 | 12 组共 82 张，点击全屏展示，中文 `clamp(30–42px)` 大字 |
| 「一键给中国人看」 | 每个场景有 `Open full screen` 按钮，输出成段的完整中文卡片 |
| 3 分钟完成 | 步骤可点击打卡，顶部有进度条 |
| 免登录、免下载 | 纯静态，无后端、无埋点、无账号 |
| 每页有 Plan B | 每个场景都有 3–4 条备用方案 |
| 每页有出口 | 任意页面可跳转急救卡片 / 紧急电话 |
| 标注更新时间 | 每页显示 `Last updated`，底部有「This info is outdated」反馈按钮 |
| 标注官方来源 | 政策类场景（Pay / Train）附官方链接 |
| 搜索 | 支持中英文关键词，如 `taxi`、`alipay`、`火车` |

交互细节：

- 步骤点击打卡 + 勾选进度记忆（`localStorage`）
- 全屏卡片：左右切换、`Esc` 关闭、方向键翻页、`Hide English`、`Copy 中文`
- 搜索实时过滤场景与卡片
- 深色模式跟随系统
- 桌面端自动收成手机宽度居中显示

```
8 个场景 · 82 张双语卡片（12 组）· 7 条 FAQ
```

场景：Pay · Taxi · Train · Metro · Hotel · Food · SIM · Emergency

## 文件结构

```
demo/
├── index.html   页面骨架 + 全屏卡片层
├── styles.css   全部样式（含深色模式）
├── data.js      内容层：SCENES / CARD_GROUPS / FAQ
└── app.js       路由 + 渲染（无依赖，约 400 行）
```

**内容与代码是分离的。** `data.js` 就是文档 [06-技术方案](../docs/06-技术方案.md) 里 `scenes` / `cards` 两张表的雏形。后续要接 Notion / Supabase，只需要替换这个文件的数据来源，`app.js` 不用动。

## 与文档的偏差（需要确认）

1. **步骤数超出规范。** [04-号文档](../docs/04-页面结构与用户流程.md) 要求「任何场景的主路径不超过 7 步」。当前 Train 是 10 步、Food 是 9 步。要么压缩步骤，要么把超出的部分移到「进阶」区。
2. **卡片数量超出第一阶段目标。** [05-号文档](../docs/05-内容模板规范.md) 定的第一阶段目标是 20 张，demo 里是 82 张。这部分是我按场景补齐的，需要内容同学复核准确性。
3. **截图红框未实现。** 文档要求「截图 + 红框 + 分步指引」，demo 里只有文字步骤 —— 需要真实截图素材才能做。
4. **内容准确性待复核。** 支付限额、12306 规则、酒店接待外籍政策都只写了操作步骤、未写具体数字，但上线前仍需对照官方渠道逐条核对。
