# 双语应急卡片 · Demo

**在线访问：<https://11kaize.github.io/ChinaPASS/>**

## 这是什么

一个**只做一件事**的工具：

> 外国人在中国遇到说不通的情况 → 打开卡片 → 全屏中文大字 → 把手机递给对方看。

单向的。只解决「我怎么说出去」，不处理对方的回话。

## 产品范围（当前阶段）

只做卡片，**不做场景 SOP**。原因：

- 卡片要的是「1 秒可达」，翻场景找卡片是反的
- 需要卡片的时候人已经在急的状态，没耐心浏览

所以整个应用就是卡片本身。

## 内容规模

```
9 组 · 59 张卡片 · 4 个应急电话
```

按**紧急程度**从高到低排：

| 组 | 张数 | 什么时候用 |
|---|---|---|
| 🆘 紧急求助 | 6 | 最急，报警 / 叫救护车 |
| 🗣️ 说不通时 | 6 | **万能卡，任何场景先用这组** |
| 🏥 医院 | 8 | 身体不舒服 |
| 🎒 丢失物品 | 6 | 护照 / 手机 / 包丢了 |
| 🔋 手机没电 | 5 | 手机快关机 |
| 🧭 迷路问路 | 6 | 找不到地方 |
| 🚕 打车 | 8 | 联系司机、报位置 |
| 🏨 酒店 | 7 | 入住、寄存、叫车 |
| 🍜 外卖 | 7 | 忌口、放前台 |

「**说不通时**」那组是新增的，之前没有，但实际最常用——`我不会说中文 / 请说慢一点 / 请写下来 / 请指给我看`。不管卡在哪个场景，先开这一组。

## 交互设计

**首页**

- 顶部一个红色大按钮「🆘 我现在需要帮助」——一点直达第一张求助卡，不用选组
- 下面是 110 / 120 / 119 / 122，手机上点了直接拨号
- 再下面才是 9 个分组

**全屏卡片**

- 中文用 `clamp(36px, 11vw, 58px)`，一行最多 14 个字，保证手机上一眼看清
- **打开 2.5 秒后按钮栏自动隐藏**，递给对方时整屏只有中文，不会误触
- 点一下屏幕可以重新调出按钮，再点一下隐藏
- 左右滑动翻页，也可以点‹ ›
- `隐藏英文`——英文行只是给你自己确认用的，递出去前可以关掉
- `复制中文`——方便粘到聊天窗口

## 文件结构

```
demo/
├── index.html   页面骨架 + 全屏卡片层
├── styles.css   全部样式（含深色模式）
├── data.js      内容层：CARD_GROUPS / EMERGENCY_NUMBERS
└── app.js       渲染 + 卡片层交互，无依赖
```

**内容与代码分离。** 要加卡片或改文案，只动 `data.js`，格式：

```js
{
  id: "hospital", icon: "🏥",
  title: "Hospital",        // 英文名
  zh: "医院",                // 中文名（首页显示的）
  hint: "沟通用语，不含任何诊断或用药建议",
  cards: [
    { en: "I don't feel well.", zh: "我身体不舒服。" },
  ],
}
```

## 已知的边界（这是有意的）

**卡片是单向的，解决不了对方的回话。**

你把中文给中国人看了，对方看懂后用中文回答你，你还是听不懂。这个问题**当前版本不处理**，原因：

- 能靠「数字」（付款金额 → 递计算器）和「手指」（问路 → 递地图）解决的场景，本来就不需要听懂
- 真正需要整句翻译的（就医问诊、纠纷调解），得靠语音翻译，那需要联网 + 后端 API，会把纯静态 MVP 拖进复杂度

先验证「外国人能不能靠卡片独立完成一件事」，再决定要不要上翻译。

## 下一步

- [ ] 找 3–5 个外国人实测，看卡片是不是真的能让他们**独立完成**一件事
- [ ] 观察他们卡在哪：是找不到卡片、看不清中文、还是对方的回话听不懂
- [ ] 如果卡在「找不到卡片」→ 做常驻入口（PWA 添加到主屏 + 直达链接）
- [ ] 如果卡在「对方回话听不懂」→ 再考虑翻译方案
- [ ] 内容复核：医院卡片的中文表述是否得体（这部分最敏感）
