# 十一、内容结构设计

每个场景内容统一使用以下模板撰写，确保风格一致、可复用、可维护。

---

## 场景模板

### 1. Task —— 这个场景要完成什么

> How to take a taxi in China using DiDi.

### 2. Before You Start —— 需要准备的东西

- Phone
- Internet
- Destination address in Chinese
- Alipay / WeChat Pay

### 3. Step-by-Step —— 分步骤说明

1. Open DiDi
2. Switch to English
3. Enter destination
4. Choose ride type
5. Confirm pickup location
6. Wait for driver
7. Show this card if needed

### 4. Common Mistakes —— 常见错误

- Entering only the hotel name in English
- Standing at the wrong exit
- Not checking the car plate number
- Canceling too late

### 5. Useful Chinese Cards —— 中文求助卡片

提供该场景对应的中英对照卡片。

### 6. Plan B —— 备用方案

如果主方案失败，提供替代方案：

- Ask hotel front desk to call a taxi
- Show address to local staff
- Use public metro instead

---

## 写作要求

| 要求 | 说明 |
|---|---|
| **英文主体** | 所有说明用英文写，面向 CEFR B1 水平读者 |
| **短句优先** | 单句不超过 15 个单词 |
| **动词开头** | 每个步骤以动词开头：Open / Tap / Enter / Show |
| **避免术语** | 不出现「实名认证」这类需要本地知识的词，必须出现时先用一句话解释 |
| **截图红框** | 关键按钮在截图上用红框标出，说明文字指向红框位置 |
| **标注更新时间** | 每页必须显示 `Last updated: YYYY-MM-DD` |
| **标注官方来源** | 政策类内容必须附官方链接 |
| **不做承诺** | 支付、签证类内容只写操作步骤，不承诺「一定能成功」 |

---

## 内容维护机制

1. 每页底部提供「This info is outdated」反馈按钮；
2. 高频场景（Pay / Taxi / Train）每 2 周检查一次；
3. 低频场景每 2 个月检查一次；
4. 建立变动日志 `content/CHANGELOG.md`，记录每次修改的原因与日期。
