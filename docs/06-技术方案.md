# 十二、技术方案设计

---

## 1. MVP 技术选型

### 前端

推荐任一：

- React / Next.js
- Softr / Glide（无代码，最快）
- 微信小程序

### 后端

第一阶段可以不用传统后端。

| 用途 | 推荐 |
|---|---|
| 内容数据库 | Notion |
| 内容管理 | Airtable |
| 后期数据库 | Supabase / Firebase |

### 多语言

- **第一阶段：** 英文为主，中文作为展示语言，暂不做十种语言。
- **后期可扩展：** 日语、韩语、德语、法语、西班牙语、俄语。

### 部署建议

| 环节 | 方案 |
|---|---|
| 静态托管 | Vercel / Netlify / Cloudflare Pages（免费额度足够 MVP） |
| 二维码 | 一个短链 + 二维码，印在卡片上投放到酒店/青旅 |
| 埋点 | 第一阶段用 Plausible / Umami，避免重量级 SDK |
| 域名 | 建议用 `chinacheatsheet.xxx`，短且可拼读 |

## 2. 数据模型设计

### 表一：场景表 `scenes`

| 字段 | 说明 |
|---|---|
| scene_id | 场景编号 |
| title | 场景标题 |
| category | 分类 |
| priority | 优先级 |
| description | 描述 |
| steps | 步骤 |
| screenshots | 截图 |
| warnings | 注意事项 |
| last_updated | 最后更新时间 |

### 表二：双语卡片表 `cards`

| 字段 | 说明 |
|---|---|
| card_id | 卡片编号 |
| scene | 所属场景 |
| english_text | 英文内容 |
| chinese_text | 中文内容 |
| use_case | 使用场景 |
| copy_button | 是否支持复制 |

### 表三：城市包表 `cities`

| 字段 | 说明 |
|---|---|
| city_id | 城市编号 |
| city_name | 城市名称 |
| airport_guide | 机场指南 |
| train_guide | 高铁指南 |
| metro_guide | 地铁指南 |
| hospital_list | 医院列表 |
| tips | 城市避坑建议 |

---

## 3. 数据模型关系

```
scenes 1 ──── n cards        (一个场景对应多张双语卡片)
cities 1 ──── n scene_tips   (一个城市包含多条本地化的场景提示)
scenes n ──── n cities       (同一场景在不同城市有不同细节)
```

> 建议：内容先以 Markdown 文件形式存放在 `content/` 目录，通过构建脚本生成静态页面。等验证需求后再迁移到数据库，避免过早引入后端复杂度。
