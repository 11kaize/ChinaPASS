# 九、页面结构设计

---

## 1. 首页

首页采用「**任务入口**」设计，是一页一页的形式：**底部导航栏分成四屏**，而不是把所有内容堆在一个长滚动页上。底部栏常驻 **4 个内容屏 + 1 个 SOS**，任意两屏之间都只隔一次点击。

| 屏 | 路由 | 放什么 |
|---|---|---|
| 落地 | `#/` | 标题、你在哪个口岸落地、紧急电话 |
| 流程 | `#/steps` | 你的路线，一步一步来 |
| 功能 | `#/features` | 九个功能网格、「所有卡片」、说话卡入口 |
| 工具 | `#/tools` | 搜索、行前准备、城市明细、地址求助卡、怎么用、常见问题、卖点 chip、脚注 |

分配原则，为的是将来往哪一屏加东西有依据：**「功能」= 能办的事（内容）；「工具」= 查东西和设置（查询 / 关于）。**

`#/` 仍指向第一屏，不新增别名，所以老链接、PWA 的 `start_url`、以及不带 hash 直接打开都落在原地。

### 底部导航栏

- **为什么有 SOS：** 本文件「流程设计原则」要求**每页都能一键跳到急救卡片**。拆屏之后，人在流程 / 功能 / 工具三屏时急救号码会退到两跳以外，所以底部栏留一个常驻的 SOS 槽位，直接指向 `#/emergency`，复用现成的 `紧急` 文案，不新增字符串。
- 四个内容标签用真 `<a href="#/…">` 锚点，不是 `data-go` 按钮：切屏本来就是 hash 变化，让浏览器自己走就有返回键和长按复制链接。页内滚动仍然必须用 `data-toc` 按钮，原因见脚本里的注释。
- 点**已经激活**的那个标签会回到该屏顶部（浏览器不会为同一个 hash 派发 `hashchange`，所以这里自己重渲染一次）。

### 落地屏

- **标题：** China Hand
- **副标题：** Your 3-minute guide to surviving daily life in China
- **你在哪个口岸落地？**
  - 15 个外国人实际能落地的口岸，含**机场 / 海港 / 铁路 / 陆路**四种。默认列出国际旅客量最高的 6 个，其余收在「更多口岸」里。
  - 另给一条国家移民管理局官方名单链接。该名单是**过境免签**口径，界面不把它说成「全部对外开放口岸」。
  - 选中后显示该口岸的**中文全名**（能直接给司机看的那一行），以及「类型 · 城市 · 三字码」。
  - 该城市的机场 / 车站中文名与易混提示若已写好，一并列出并给「城市指南」入口；**没写的口岸如实说明还没写**，不给空块、不给会跳到「未找到」的链接。
- **紧急电话：** 110 / 120 / 119 / 122，常驻这一屏，右侧给求助页入口。不参与任何折叠。

### 流程屏

- 节点即场景。点一个节点同时做两件事：进入该场景页，并把它标成「你在这」——所以「我到哪一步了」不需要单独设置一次。
- 落地当天：海关 / 入境 → 电话卡 → 支付 → 打车 → 酒店
- 安顿之后：地铁 → 高铁 → 外卖
- 默认停在第一项；**不从行前清单的完成状态反推**当前进度。
- 紧急求助**不在路线里**：它是 `eta: 立刻` 的 P0 项，不是落地后走到的一站，所以它只出现在落地屏的常驻条和底部栏的 SOS 上。
- 从陆路 / 铁路口岸入境的用户会多看到一行说明：这类口岸没有取行李这一步（`customs` 场景的步骤是按机场写的）。

### 功能屏与工具屏

原首页第一屏以下的内容全部保留，只是各自成屏：九个功能网格与「所有卡片」在功能屏；搜索、📍城市、🪪地址求助卡、❓怎么用、行前准备入口、城市明细、常见问题、四个卖点 chip、脚注在工具屏。八个 chip 按上面的分配原则拆开：说话卡（💬）在功能屏，其余七个在工具屏。

### 存储

- `ccs.port`（口岸 id）与 `ccs.stage`（当前场景 id）为口岸改版新增键。
- `ccs.city` 的格式与含义不变，仍存 `CITY_BOXES` 的英文城市名。按口岸选择与手动选城市**走同一个写入口**，避免出现「城市是北京、口岸挂着上海浦东」。
- 分屏**不复用 hash 存选中标签**：当前在哪一屏由 hash 本身表示，刷新与返回键因此天然一致，没有第二个真相。

# 十、核心用户流程

---

## 流程一：外国游客使用打车指南

1. 用户到达中国；
2. 需要去酒店；
3. 扫码打开 China Cheat Sheet；
4. 点击 "Taxi"；
5. 查看如何输入酒店地址；
6. 复制中文地址给司机；
7. 展示双语卡片；
8. 成功上车。

---

## 流程二：外国游客购买高铁票

1. 用户计划去另一个城市；
2. 点击 "Train"；
3. 查看 12306 注册流程；
4. 填写护照信息；
5. 查看车次；
6. 理解候补机制；
7. 支付票款；
8. 查看进站指南；
9. 到站人工核验护照；
10. 成功乘车。

---

## 流程三：外国游客使用 Alipay

1. 用户想付款；
2. 点击 "Pay"；
3. 查看绑卡步骤；
4. 输入国际银行卡信息；
5. 完成验证；
6. 查看支付限额；
7. 如果失败，查看备用方案；
8. 成功完成支付。

---

## 流程设计原则

| 原则 | 说明 |
|---|---|
| 3 分钟内完成 | 任何场景的主路径不超过 7 步 |
| 英文优先 | 英文为界面主体，中文为展示内容 |
| 无需登录 | 不强制注册，打开即用 |
| 每页有 Plan B | 主方案失败必须有替代路径 |
| 每页有出口 | 随时能一键跳到急救卡片 |
