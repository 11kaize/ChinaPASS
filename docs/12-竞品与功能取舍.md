# 同类产品观察与功能取舍

本次访问了 [chinapass.app 中文站](https://chinapass.app/zh-CN/) 的首页、[城市目录](https://chinapass.app/zh-CN/cities/)、[攻略目录](https://chinapass.app/zh-CN/guides/) 和 [App 介绍](https://chinapass.app/zh-CN/app/)。其可借鉴的产品流程是：先选城市，再按主题获取准备信息，最后把必要内容留在离线可用的应用里。我们只借鉴信息架构与功能方向，城市文案、交互实现和主视觉均为本项目原创。

## 这版 Demo 的落实

- **行前清单：** 把付款方式、中文地址、离线翻译、车票信息和紧急联系人列为准备项。勾选保存在当前设备。
- **实用旅行指南：** 保留仓库中的 9 个完整场景，覆盖行前材料、步骤、易错点、备选方案、问题排查及来源。
- **情境短句：** 保留 14 组 96 条中文短句及多语释义，支持搜索和全屏展示。
- **离线入口：** PWA 缓存应用外壳和静态内容。Electron 桌面版直接从本地文件运行。
- **紧急电话：** 首页列出 110、120 和 119；求助卡和紧急指南提供可点击的拨号链接。拨号依赖设备电话能力，不是应用内求助服务。
- **城市速览：** 八座城市可按名称、区域、主题或看点筛选；详情页提供简短亮点、饮食与预约提示，并链接到官方或权威来源。
- **行程草案：** 本机保存城市、顺序与天数；7 天和 10 天路线只是可编辑起点，没有虚构价格或可用车次。
- **攻略目录：** 原有九个情景任务和三篇新增的证件核对、景点预约、离线准备短攻略，可按主题检索。新增摘要目前为英文。
- **个人地址卡：** 用户自己填写中文地址，生成全屏展示卡。地址只保存在当前设备，可一键清除；未填写地址时无法打开卡片。

## 外链直达：交接，不是代办

地图路线、支付、打车、铁路购票和实时翻译都需要官方服务和第三方接口，静态 Demo 无法在应用内完成，也不应把行程草案描述成预订功能。**这条底线没有变**：本应用不代下单、不收款、不经手任何交易，没有后端也没有任何一方的 API。

改变的是「然后呢」。原先九个指南里只有六个有外链，而且是页面最底部一行 12px 的小字，读起来像署名而不是入口；打车、地铁、美食三个指南一条链接都没有，酒店那条还错挂到了移民管理局。现在每个指南顶部都有一个「直接去办」面板：

- **官方优先**：12306、支付宝、滴滴、高德、中国移动 —— 服务本身的官方入口。
- **英文友好为辅**：Trip.com 等，给卡在注册或中文界面上的用户一条退路。
- **每条都带徽章**（官方 / 英文友好 / 中文界面 / 拨打），点之前就知道自己要打开什么、要不要花钱。美食那两条（大众点评、美团）特意标「中文界面」而不是「英文友好」——本地人确实用它们，但说明里写着要中国手机号，标成英文友好就是骗人。
- 城市详情页的机场与车站中文名可直接跳高德搜索；紧急指南的 110 / 120 / 119 / 122 补上了拨号链接（此前只出现在首页）。

外链一律 `target="_blank"` 在新标签打开，并明说需要联网——服务工人壳离线可用，但外链不行。桌面端 `electron/main.cjs` 只把 `https:` 和 `tel:` 交给系统，所以链接必须是 https。

链接会失效，这是这种做法的固有成本。仓库根目录的 `scripts/check-links.mjs` 会抓取所有外链并逐个探测，发布前跑一次：`node scripts/check-links.mjs`。

**海关总署那条是主动删掉的，不是漏了。** `www.customs.gov.cn` 的 https 拿不到有效证书——边缘节点返回的是 CDN 默认证书（`default.ssl.cdn.jiasule.com`），浏览器会直接弹安全警告，https 状态码 504；而 http 能用。可桌面端只放行 https，http 在那里是「点了没反应」的静默失败。同一个场景里移民管理局的 https 已验证可用，且入境政策和申报规定都查得到，所以宁可留一条站得住的链接，也不要第二条看运行方式才决定能不能用的链接。
